# FRE0001: Use `""` instead of `string.Empty`

| Property | Value |
|---|---|
| Rule ID | FRE0001 |
| Category | Style |
| Default severity | Warning |
| Code fix | Yes (supports fix all) |

## Cause

`string.Empty` is used where the empty string literal `""` could be used.

## Rule description

`""` is a compile-time constant, `string.Empty` is a `static readonly` field. The literal can therefore be
used everywhere, including places where `string.Empty` is a compile error:

```csharp
const string Name = "";                  // error with string.Empty
[Obsolete("")]                           // error with string.Empty
void M(string s = "") { }                // error with string.Empty
switch (s) { case "": break; }           // error with string.Empty
```

Using one form consistently also avoids having to choose between the two in every code review.
The analyzer detects `string.Empty`, `String.Empty`, `System.String.Empty` and `Empty` via
`using static System.String`. `nameof(string.Empty)` is ignored.

## How to fix violations

Replace `string.Empty` with `""`. The code fix (<kbd>Ctrl</kbd>+<kbd>.</kbd> in Visual Studio / Rider,
<kbd>Cmd</kbd>+<kbd>.</kbd> in VS Code) does this for a single occurrence, or for a whole
document/project/solution with **Fix all**.

```csharp
// Before
var name = string.Empty;

// After
var name = "";
```

## When to suppress

If your team deliberately prefers `string.Empty`, disable the rule in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.FRE0001.severity = none
```

Or suppress a single occurrence:

```csharp
#pragma warning disable FRE0001
var name = string.Empty;
#pragma warning restore FRE0001
```
